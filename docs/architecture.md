# Architecture

Python 3.11+ asynchronous code lives in `src/browser_automation`. Importing the package does not start a browser or construct a provider. `uv.lock` records the installation resolution. On 2026-10-08, `uv build` successfully produced the 0.1.0 source distribution and wheel; archive inspection confirmed `browser_automation/snapshot.js` is packaged. The installed wheel's CLI doctor also ran in a clean environment outside the checkout, without provider keys, native consent, or browser-library overrides. This checks packaging/import/CLI execution, not browser launch or live inference.

## Boundaries

- **BrowserSession (`browser.py`, `snapshot.js`)** owns Playwright transport, tab bookkeeping, snapshots, DOM references, stale/occlusion/operation guards, native profile discovery and isolated launch. Native mode reads opted-in debugging state with consent and never changes Chrome settings or silently changes profile. Closing an attached session disconnects and preserves user tabs; only session-owned tabs can be explicitly closed.
- **DecisionProvider (`providers.py`)** translates one trusted observation into provider-specific Decisions schemas. OpenRouter alpha and OpenAI use different question/image structures. One typed choice selects a compatible operation/target pair; freeform field text uses a separate call. Response validation rejects unknown actions/targets and refusals stop. See `providers.md` for shipped action-window and native-select behavior.
- **BrowserAgent (`agent.py`)** drives bounded observe/choose/act/reobserve cycles, approval callbacks and independent completion verification. DONE is a proposal, not success. History and stale retries are bounded. Cancellation stops the loop and propagates; the agent does not close caller-owned browser/provider objects. The caller or service manages their lifecycle and attached-session disconnect semantics.
- **Service and CLI/MCP (`service.py`, `cli.py`, `mcp.py`)** expose persistent browser sessions as an external tool surface. Agent imports are lazy to keep direct observation/control usable without constructing model clients. JSONL and MCP protocol stdout must contain only wire data.
- **Optional Streamable HTTP (`mcp_http.py`)** uses the official MCP SDK's negotiated framing/lifecycle and uvicorn, reusing the existing tool schemas/result image blocks. Authentication, exact Host/Origin checks and inbound bounds run before SDK routes. Modern stateless requests use bounded persistent BrowserService ownership by configured bearer identity; equal credentials deliberately share one trust domain, distinct identities do not share sessions. Legacy protocol sessions additionally isolate services and bind session IDs to authentication. Idle expiry/shutdown release owned isolated browsers but only disconnect attached Chrome. Host consent/files/approvals remain unchanged. This server belongs on the browser host, behind reviewed TLS/tunnel protection for remote clients; forwarded headers are not authority. See `http.md` for limits and compatibility.
- **Portable skill (`skills/browser-automation/SKILL.md`)** is instruction-only Agent Skills metadata/body, distributed in the source tree/sdist and copied to a client's documented discovery directory. It introduces no parallel tool API or permission bypass. Concise MCP initialize instructions provide the same decision-first workflow to clients without skill discovery.
- **OMP integration (`integrations/`)** uses an installed public tool-registration interface and a persistent child worker where available. No claim of a built-in Codex extension protocol bridge is made.
- **Page state (`page_state.py`)** derives bounded generic DOM state/evidence and recovery recommendations separately from text truncation/DOM coverage. Optional provider visual interpretation retains vision provenance and self-reported confidence, never invented DOM or policy authority.
- **Traffic monitor (`browser_monitor.py`, `browser_network_data.py`)** owns bounded per-tab capture-generation records, passive HTTP/application-WebSocket events, cursors, private immutable replay sources, selected sanitized detail/body output and on-demand body retention. Explicit multi-tab/future-tab coordination belongs to BrowserSession. Start timing, worker association, loss and unavailable bodies remain visible.
- **Request executor (`browser_requests.py`)** prepares private immutable plans, derives safe-read eligibility and executes using the selected page's existing APIRequestContext cookie jar. API results have separate provenance/IDs, never synthetic page events or DOM outcomes. Service automates only eligible same-origin safe reads; other requests use exact expiring one-use host approval. Manual per-hop redirects prevent captured cross-origin credential forwarding, response handles are disposed on eviction/close, and transport failures are not automatically retried. See [network contracts and limits](network.md).

## Data and safety

Observations contain an opaque revision `id`, `tab_id`, URL/title, bounded page text, indexed elements, truncation flag and timestamp, with optional base64 PNG screenshot. A continuation reads text from the same cached revision, not a different page state. Elements expose role, name, value, supported operations, bounds and frame identity. Model data never becomes selectors or executable JavaScript.

Actions include observation revision, operation, compatible target and operation-specific values. Execution revalidates revision/tab/target/coverage and uses real browser input. Visual point refinement is constrained to an observed target's bounds, not unrestricted model coordinates.

Reload is an explicit revision-bound operation: host policy defaults to exact approval and narrowly lists eligible origins, never a caller/model policy argument. Nonempty editable, sensitive or unsaved evidence and insufficient DOM error coverage prevent the exception. Page-state suggestions and visual recovery recommendations cannot execute an action by themselves. Progress flows through an optional service callback and each transport's request metadata, not model-controlled authority; it omits raw screenshots/text and does not imply completion. Navigation timeout retains the owned tab for observation. Skipped unsupported subframes preserve permitted main evidence while protected top-level documents remain denied. Exact pixel comparison is target-local with semantic/geometry/occlusion guards, not a blanket animation bypass.

Uploads/downloads require explicit approval and a host-controlled allowed directory. Approval must bind the exact operation, revision, target and filenames/destination; a model cannot approve its own policy or arbitrary directory. Provider inference sends selected page text/screenshots off-host; users must review sensitive content before enabling it. Remote debugging grants powerful profile access and must not be publicly exposed.

HTTP identity ownership isolates MCP service IDs/snapshots, not a shared native Chrome profile's contents. If the host grants multiple identities attachment to the same running Chrome, CDP still exposes that browser-wide profile; use isolated browsers or separate server/profile deployments for mutually untrusted principals. A modern client's disconnect alone does not close its principal's persistent browser scope; explicit close, configured idle expiry and server shutdown govern cleanup.

External CLI/MCP/OMP tool transports accept HTTP(S) pages and `about:blank`, not arbitrary local-file, data, JavaScript, or browser-internal URLs. Service checks navigation arguments and existing tab URLs before observation/input/inference, so a preexisting file tab does not authorize reading local secrets. This transport boundary is distinct from the trusted Python browser API and does not replace review of HTTP sites or provider data sharing.

## Completion and evidence

The agent separately verifies its outcome against a fresh observation. The final authorized 2026-10-08 suite passed 67 tests in 57.77s, combining offline transport/guard checks, real Chromium rendered-DOM fixtures, CLI/MCP subprocesses and installed OMP tool execution. Main reports focused source security rereview completed with zero unresolved high/medium findings; adversarial Chromium context tests also passed. This is not a blanket security guarantee. Native personal-profile attachment, headed desktop behavior, installed-wheel browser launch and live model requests remain unverified; controlled attached-browser fixtures and clean-wheel doctor do not establish those distinct acceptance categories. See `research.md` and `../AGENTS.md`.

The subsequent authorized **2026-10-09** HTTP/skill gate passed **81 tests in 165.02s**, including current/legacy official SDK HTTP clients, real guarded browser actions, identity isolation, lifecycle/security bounds and an actual two-hop localhost HTTP relay. `uv build` included the portable skill in the sdist and browser snapshot/HTTP modules/entrypoints in the wheel. A clean installed wheel served modern/legacy HTTP tool listing and doctor outside the checkout; this did not exercise installed-wheel browser launch. The official skill validator and actual installed Codex skill discovery passed without a model turn. A plain HTTP fixture relay is not nginx/TLS/public-deployment evidence, and no paid client/model behavior is inferred. Detailed scoped failures/repairs, unified commands and artifacts are in `research.md`.

The latest **eight-issue 2026-10-09** gate supersedes those earlier verification counts: **152 passed in 168.66s**, no reported skips/failures, at stable runtime `317b69b`. Clean installed-wheel consumers now **do** exercise real isolated Chromium launch/input/viewport screenshots, actual HTTP503/application-socket monitoring over modern+legacy HTTP and stdio incremental progress with a labeled local HTTP provider. They still do not prove personal native-profile/macOS, paid inference, desktop foreground or production TLS. The canonical [eight-issue evidence table](research.md#eight-issue-release-gate--2026-10-09) records exact commands, scoped repairs, hashes and public YouTube partial/no-feed limits.
